# 需求与渐进关卡返工 V0.2

2026-11-11（北京时间）。本轮修复的是“旧四项选对、填任意解释就能继续”的规则漏洞，并提供实际可调用的渐进练习门槛。不是再给旧表单加一句免责声明，也不通过字符串猜测任意中文理解。

本分支只修改 `content/`、`tests/content/`、`docs/course/`，不改 `QuestApp`、`src/tutorial/`、UI 或手册。E 负责持久化、身份作用域、页面接入和整体验收；NPC 线消费只读教学事实。基础/变更的独立客户测试文件与比较器保留原样。

## 已实现的规则

- 旧 `checkRequirementSelections` 仍提供 `draftComplete` 以显示历史草稿覆盖，但 `readyForSubmission / readyForPractice / readyToAdvance` **永远为 false**。旧保存标志不迁移成新评审证据。
- 基础需求 1.0.0 有六个顺序情境：当前光照输入、暗时输出、已亮后变亮的关闭动作、再次变化时重新读取、严格等值边界、另一组输入的迁移预测。只呈现当前题，公开选项没有正确标记。
- 变更需求 1.1.0 有四个顺序情境：500 的新旧差别、新等值边界、在自己代码中定位比较部分、使用新版确切作品测试而非旧报告。
- 每题都有 `not-sure` 和显式 `need-help`；错误、求助和未知选项分别给具体诊断、可执行小观察与同题重试。求助不扣资格，不悄悄覆盖作品。
- 原话不参与判对。有限明确求助句（包含原验收句“我完全不懂，随便选的。”）只保守转引导，其余文本保持 `not_semantically_evaluated`。这不是通用语义识别；结构化情境中的矛盾动作、错误边界和过时规则能由固定规则检出。
- 评审只保存原始回答；每次恢复重新核对顺序、选项、求助、个人、尝试和版本。不能保存一个可信的 `passed:true` 来绕过重演。
- 修改前题会重新打开该题，后续结论失效；历史回答保留。改对前题也需重做其后的迁移检查。相同 `responseId` 重试幂等，换答案复用 ID 拒绝。

`ready` 只证明本版这些具体情境的选择与客户行为一致，不能证明任意语言理解、完整知识掌握或实物完成。开发者已编写正确路线也不等于零基础学生已实测通过。

## 需求 API：E/NPC 的确定接口

从 `content/requirements-review.js` 或 `content/index.js` 导入：

```js
import {
  createRequirementReview, getRequirementChallenge,
  reviewRequirementAttempt, summarizeRequirementReview,
  requirementTutorialFacts,
} from './content/requirements-review.js';

const binding = {
  learnerId: 'synthetic-learner-1',
  attemptId: 'whole-order-attempt-1',
  requirementRef: {id: 'eq-requirement-auto-lamp', version: '1.0.0'},
  // E 可带其公共规范计算的 digest；存在时必须与保存绑定逐字匹配。
  // lessonRef 可省略，由 D 填 {id:'eq-auto-lamp-requirements', version:'0.2.0'}。
  // artifactRevision 可选，用于把一次评审固定到某个额外作品上下文。
  // requirementsEpoch 可选，显式绑定 E 的评审重置代次（非负整数或版本文本）。
};
let review = createRequirementReview({binding});
const challenge = getRequirementChallenge({review, binding});
const result = reviewRequirementAttempt({
  review, binding,
  attempt: {
    responseId: 'explicit-answer-1',
    checkpointId: challenge.checkpointId,
    optionId: 'not-sure',
    confidence: 'need-help', // 或 ready-to-try
    // explanation 可选，保留原话但不据它判对。
  },
});
if (result.accepted) review = result.review;
const summary = summarizeRequirementReview({review, binding});
const npcFacts = {requirementReview: requirementTutorialFacts(summary)};
```

持久化 `review` 的原始 JSON，不只存 summary；恢复再调用 `summarizeRequirementReview`。`whole-order attemptId` 可保持稳定，基础与变更由 `requirementRef` 区分。评审重置/epoch 必须生成或绑定新上下文，保留旧记录而不恢复旧 proof。

`summary` 关键字段：

| 字段 | 含义 |
| --- | --- |
| `status` | `in-progress / needs-retry / needs-help / ready / stale / invalid` |
| `current` | `{checkpointId,title,number,total}`；完成后为 null |
| `stageId` | 基础 `requirements`；变更 `short-code` |
| `challenge` | 当前的 `prompt`、`scene`、`options[{optionId,label}]`、手册节号；完成或失效时为 null |
| `diagnostic` | `code/message/observedFact/manualSection`；已知错项另带题与选项 ID |
| `guidance` | 错误/求助时的 `{id,title,observation,tryThis}`，只针对当前问题 |
| `retryAction / actionTarget` | 打开观察、重试、定位题目或练习的导航意图，不执行保存、批准、测试或奖励 |
| `readyForPractice / readyToAdvance` | 仅当前完整情境重演为 `ready` 时为 true，仍不是程序或硬件通过 |
| `evidence` | 仅 ready 时包含绑定、lessonRef、有效回答 ID 以及 `responsesCanonical` |

`responsesCanonical` 是**canonical JSON 字符串**，内容为全部原始回答数组（对象键排序、数组保序）。E 对该字符串的 UTF-8 字节使用公共 SHA-256，形成 `responsesDigest`，并将它与完整 `binding / lessonRef` 一起绑定测试快照。D 不另造摘要算法、不签发权限，也不验证浏览器传来的摘要真实性。

NPC 只读 `requirementTutorialFacts(summary)`，它移除证据 payload 和原话，没有答案键。NPC 的“下一句/跳过/重看”不调用 `reviewRequirementAttempt`；宿主的明确作答动作才提交选项。未知中文仍未解析，不能由 NPC 文案宣称已理解。

## 七项渐进工程练习

通过需求情境只打开当前练习，不自动完成程序。`getLearningProgression()` 返回公开任务目标、顺序与手册节号，不返回情境答案。当前是一份订单拆成可观察的渐进练习，尚未伪造更多完整客户订单。

| 活动 ID | 玩家实际动作与可见反馈 | 需要的事实代码 | 合法来源 |
| --- | --- | --- | --- |
| `observe-output` | 在虚拟引导实验里改变 LED 状态，说明这是输出；不记为完整自动灯 | `guided_output_observed` | A 实际运行记录 `program-runtime` |
| `read-input` | 放读取/变量，改变虚拟光照，观察当前读数跟着变 | `current_input_read_observed` | `program-runtime` |
| `branch-output` | 搭比较与两个分支，对暗、亮分别观察输出 | `dark_branch_observed`、`bright_branch_observed` | `program-runtime` |
| `repeat-read` | 在同一次运行中经历暗→亮→暗，检查重新读取 | `repeated_current_read_observed` | `program-runtime` |
| `base-delivery` | 自己组合完整程序，运行冻结基础客户测试并排错 | `base_customer_suite_passed` | D/A 整套客测 `course-customer-tests` |
| `code-mapping` | 保留自己的积木，显式点选比较节点并在自己的代码找到对应位置 | `own_blocks_snapshot_preserved`、`own_comparison_mapping_observed` | `snapshot-store`、A 映射 `program-analysis` |
| `change-delivery` | 保存确切修改版本，再运行完整新版独立测试 | `changed_exact_source_recorded`、`change_customer_suite_passed` | `snapshot-store`、`course-customer-tests` |

`fullAnswerAllowed:false` 表示主线教学不能靠自动加载整题答案完成这些活动。完整协助方案不能记为独立完成，支持来源需由宿主如实保留。是否编译、是否烧录仍分别标记未实现或延后，不能填成功。

## 进度 API 与失效依赖

```js
import {deriveLearningProgress, getLearningEvidencePolicy} from './content/learning-progress.js';
const progress = deriveLearningProgress({
  requirements: {review: baseReview, binding: baseBinding},
  changeRequirements: {review: changeReview, binding: changeBinding}, // 尚未进入时可省
  context: {
    learnerId, attemptId,
    base: {requirementRef: baseRef, requirementsEvidenceKey: baseProofKey, wiringKey, blocksKey},
    change: {requirementRef: changeRef, requirementsEvidenceKey: changeProofKey, wiringKey, blocksKey, sourceKey},
  },
  observations: [{
    id: 'runtime-observation-1',
    activityId: 'observe-output',
    learnerActionId: 'explicit-observe-output-action-1',
    source: 'program-runtime',
    binding: {learnerId, attemptId, requirementRef: baseRef,
      requirementsEvidenceKey: baseProofKey, wiringKey},
    factCodes: ['guided_output_observed'],
  }],
});
```

键由 E 的当前事实生成：`requirementsEvidenceKey` 必须依据当前绑定/lessonRef/回答重算，`wiringKey` 是连接语义而非画布位置，`blocksKey` 绑定自己的积木/程序版本，`sourceKey` 绑定确切文本。D 比较这些明确键，**不会验证一个随意自报的 key 确实来自正确内容**，宿主必须负责实际计算与来源。

观察按实际事件顺序保存，记录需要明确 `learnerActionId`。同一 action 不能跨多个 activity 自动补齐学习；下一句、导航、看过物品不产生工程观察。未来活动预填在前面的记录不能快进；`programReady:true`、UI `passed` 或一次客测通过不会替代七项练习。

| 事实 | 依赖范围 | 修改后处理 |
| --- | --- | --- |
| 引导输出 | base 的个人/尝试/需求引用/需求 proof key/接线 key | 接线或需求变更需重新观察，积木变化不会删除已做的引导输出 |
| 读取/分支/持续读取/基础测试 | 上述 base 依赖 + blocksKey | 程序或积木变更使后续当前证据过期 |
| 保留自己的积木 | **base** 绑定 + blocksKey | 客户变更问答尚未完成也可先保留；不依赖 change proof 或 sourceKey |
| 比较节点映射 | change 绑定 + blocksKey | 需先完成变更情境；当前学习针对保留积木对应代码，不因随后修改文本反复重做 |
| 修改后源码/新版客测 | change 绑定 + blocksKey + sourceKey | 文本变化必须重新保存、复测；旧记录保留为历史 |

`getLearningEvidencePolicy()` 导出准确的 `sourcesByFact / dependenciesByFact / phaseOverridesByFact`，避免集成另抄一张不同的依赖表。准备代码变更的正确顺序是：基础交付通过 → 保留 base 积木快照 → 揭示变更 → 完成 change 情境 → 显式代码映射 → 修改自己的文本 → 新版复测。

返回 `checkpoints` 含 `state: locked/pending/stale/observed`、`missingFacts`、具体目标/诊断/手册定位；`current/currentMilestoneId` 指向第一项未完成。`readyForBaseTests` 在前四项操作观察后开启，`readyForCodeChange` 要基础交付事实，`readyForChangeTests` 要变更情境和映射事实；七项及两个情境门槛齐备才有 `learningComplete / readyForSoftwareDelivery`。这个结果不发钱、不批准实物。

这些 observation 是 E 从 A/B 的实际运行/分析、D 的完整客户测试和不可变快照中提取的事实，不是学生直接上报的数据。D 会检查来源类型、动作、顺序与绑定；本地函数不能独立证明来源真实性，生产权限也未实现。E 不得根据一个模型评价或 `passed:true` 随意组装缺失事实。

## 实际可运行的开发验收路径

```sh
node content/learning/verify-path.mjs
node --test tests/content/*.test.js tests/*.test.js
node content/demo.js
```

第一条实际调用新规则：先复现原句反例，再走 unknown → 求助 → 局部重试 → 六个基础情境 → JSON 恢复重演 → 四个变更情境；最后改答边界并检查旧证据失效。它是开发者合成逻辑回放，不是零基础学生浏览器体验验收。第三条保留原独立客户测试的错误阈值/错误输出/旧程序拒绝演示。

网页集成后必须由我们先实际游玩下面路径，再邀请用户验收：

1. 新合成身份领取校园自动灯订单，看到具体环境变化；入口没有整套答案或预填四项。
2. 第一题选时间，看到“同一时刻不同光照”的具体观察；选不确定后能重试，不回到泛泛欢迎语。
3. 只完成前四题仍不能进入工程练习；在等值和迁移题中答错，应停在对应题并可纠正。
4. 完成六题后保存绑定证据，刷新后由原始回答重演；修改前题后旧通过消失、历史保留。
5. 逐步做输出、读取、双分支和持续读取，空白画布先显示当前目标与局部指导；不能靠加载整题或一次运行补齐所有学习。
6. 自己提交基础客测，再保留积木、完成变更情境、点选对应比较代码、预测 500、修改并复测。旧 450 程序应被新版测试拒绝。
7. 改接线/积木/源码后核对恰当的证据过期；重新完成所需操作，收入/历史恢复由 E 验收，不靠 D 返回的钱字段。

## 验证事实与未完成项

已在本分支运行：59 项测试通过（49 内容、10 旧引擎）。覆盖原验收句、未知选项、不确定、明确求助、矛盾明暗动作、等值/迁移失败、幂等/冲突回答 ID、跳题、伪造通过、个人/尝试/版本不匹配、历史重演、改答撤证，以及实践观察的来源/顺序/依赖失效。独立客户测试未改写。

仍需 E/NPC/A/UI 接入和实际浏览器游玩验收；本交付不宣称游戏或教学整体已合格。真实初学者试教未完成，任意中文语义评审未实现。当前只有一份基础订单及一个客户变更、七项渐进练习；商城、真实账号、多人榜和教师后台未实现。烧录按用户决定延后，不能作为当前软件门槛或冒称已完成。
