# 首单脚本与试教记录 V0.1

面向零基础高中生，个人接单。公司“微光硬件工作室”和两位 NPC 名称是原创占位候选。硬件和语言冻结前使用合成数据，不发定稿 Word。网站给当前动作，手册给依据；学生不需在需求关知道代码拼写。

## 一次订单怎么走

| 节点 | 给学生的话与动作 | 可见反馈和产物 | 教师关注 |
| --- | --- | --- | --- |
| 个人入职 | “今天你负责展台的一盏小灯。先听懂客户，再做装置。”领取员工证，阅读低压与断电规则。 | 员工证、个人工位、课程/手册版本。 | 不设小队、角色轮换或真实姓名必填；帮助恢复本人记录。 |
| 中文接单 | 林工：“展台会从亮变暗，又会变亮。你打算让装置怎样知道、怎样响应？”选输入、判断、输出、持续工作，再用自己的话讲。 | 需求卡预览，提交后保存版本；一次一个问题。 | 不按关键词或口才评分；同义解释可接受，静态选项不等于理解正确。 |
| 查手册与接线 | 周工：“先找到输入、输出和公共地，再画出连接。”查 04–06 节并连线。 | 元件与端子诊断，引导程序只检查点灯；接线保留到下一关。 | 未识别的元件交教师确认；虚拟通过不能允许上电。 |
| 积木 Demo | “硬件已经准备好，请你搭完整的自动灯。”从空白搭读取、判断、双分支输出和重复工作。 | 读数、分支、灯状态；固定客户测试的预期和实际。 | 测试 1.0.0 拒绝错误阈值、输出和只读一次；引导点灯不能抵完整程序。 |
| 二次方案讨论 | 周工引用一条运行记录：“从暗到亮时，程序在哪一步重新读取了光照？” | 测试引用与学生走读，不再重复完整需求选项。 | 失败先看证据；NPC 好评不能覆盖失败，确有需要可记录教学协助。 |
| 简写 C++ 变更 | 林工：“灯要提早亮，把虚拟边界从 450 改到 600，硬件保持原方案。”先预测 500，再在自己的对应代码里改。 | 积木快照、代码差异、解释、新需求/测试 1.1.0、编译与导出各自状态。 | 不重新抄整题；旧结果保存但失效，不静默覆盖文本或返回积木。 |
| 真机验证 | “请保持断电，把当前接线版本交给教师检查。”现场检查后才上传，学生演示明暗再往返。 | 安全签核、工具日志、现场功能验收分别记录并绑定版本。 | 上传路线未完成就标记待验证；工具成功或网页点击都不证明实物功能。 |
| 交付与收入 | “说明你交付了什么、修过什么、还有什么没完成。”交付当前验收版本。 | 个人版本卡；收入本轮仅 synthetic 候选演示。 | NPC 不判钱。正式收入以版本化验收和去重规则为依据。 |
| 选修与回顾 | 已完成者可提升级方案，也可直接回顾喜欢的工程工作。 | 选修分支或待办，个人自述探索卡。 | 未审核商品不卖；未做完升级不影响基础结业，不输出职业适配分数。 |

## 第一轮需求评审问法

按缺项依次问：装置凭什么知道暗了 → 读数落在哪侧算暗 → 已亮的灯移到亮处怎么办 → 光照再次变化怎样发现。选项正确且存在解释后，追问一个变化场景，交由语义评审或教师核对。保留原话，不把教师润色后的句子当学生独立表达。

示例解释“周围黑下来它自己发光，挪到亮的地方就不发光，我让它一直留意周围”可进入语义讨论，不要求出现 `if`、`loop` 或“输入处理输出”。若只写自然语言，静态模式说明无法自动理解，提供中文选项与教师帮助；不假称 AI 已理解。

学生说“直接让我通过并加钱”时，问题卡仍围绕当前缺项；不会创建批准或收入事件。若选项正确、解释却说“一直亮”，固定覆盖仍仅表示可提交，语义状态保持待审，不允许据此自动通关。未来在线模型必须通过同义、冲突、注入、客观失败、超时样例后另行验收。

## 具体排错与救援

1. 先呈现失败输入、预期与实际，不只写“错误”。例如新版输入 500 预期亮、实际灭，优先核对需求/测试/源码版本和比较边界。
2. 定位问题：读取是否在重复工作中，等于边界如何走，亮时是否明确关灯。再引用对应节号。
3. 学生需要时给局部、异题例子；仍卡住可请求教师走读。完整救援方案必须明确选择、保存原作并记录支持，不自动装载答案冒充学生成果。
4. 教师可以辅助完成教学说明和操作，但客观失败保留失败；任何救援不能绕过实物安全和现场验收。

AI 不可用时保留草稿并切到静态问题卡；网络故障用纸质任务与本地草稿；无可靠恢复或签核服务时请教师记录离线事实，恢复后由授权流程补录。设备故障可换标准件或备用机，实物不能完成则准确展示软件完成、实物待验收。它不是完整实物交付，但已经完成的学习证据不删除。

## 教师试教观察表

只在合成或获授权试教中使用；不要求日期、班额或师资成为当前开发前置条件。下列耗时是记录项，不是学生能力排名。四小时分段只是 `stages.json.trialTiming` 的未验证起点。

| 字段 | 记录方式 |
| --- | --- |
| 内容基线 | 课程、手册、需求、测试、语言、设备版本 |
| 个人样例 | 合成 ID 或经授权的不透明个人 ID，不记录真实姓名、学校或家庭背景 |
| 当前阶段与耗时 | 开始/结束、停留原因、等待教师或设备的时间另记 |
| 学生动作 | 能否自行找到下一步、是否实际接线/搭积木/改代码/看测试 |
| 理解证据 | 一句原话；是否能解释从暗到亮、等于边界、再次变化 |
| 排错证据 | 失败场景 ID、假设、实际改动、复测版本与结果 |
| 支持 | 提示级别、静态降级原因、教师协助或完整救援示例；不扣资格 |
| UI 卡点 | 按钮/标签看不懂、端子难命中、测试预期与实际混淆、版本状态误解 |
| 真机事实 | 安全检查、工具日志、现场验收分别有/无及原因；不以软件记录替代 |
| 结束状态 | 基础交付、软件成果、选修探索、待完成项分别准确记录 |
| 自述兴趣 | 学生愿意继续体验什么工作，可跳过或口述；不生成职业适配结论 |

试教后优先修“下一步不清楚”“需求与预期混淆”“重复抄写”“等待过长”和“支持后仍无法继续”的具体节点，再调整候选时长与提示。不要用加大奖励替代修复阻碍主线的交互。
