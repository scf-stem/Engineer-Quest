# 首单沉浸感审查与可验证小样 V0.3

2026-11-11 · C 线 · 对照 V0.2 工位、邮件、工作台与素材截图

用户希望接近 ARPG 的代入感。本轮把它解释为空间探索、明确目的、人物交流与行动反馈；不推导出战斗、3D、人物移动或复杂数值系统。判断依据是现有界面及实际操作，尚无真实学生试玩证据。

## 审查结论与本轮改进

| 现有表现 | 对沉浸体验的影响 | 已实现的小样 |
|---|---|---|
| 公司只存在于顶部场景横幅，工作主要是切卡片 | 学生在看办公网页，缺少“我在这里”的空间感 | 原创暮色研发室占据主画面；邮箱、元件台和林工形成三个可辨认的空间区域 |
| 六段路线说明阶段，缺少一个立即可做的任务句 | 容易先找按钮，忽略委托目的 | 受控任务追踪器：`读懂自动灯委托，保存我的中文方案卡`，附当前行动说明 |
| NPC 在侧栏一次显示整段话 | 有人物图，但缺少交流节奏 | 人物立绘与短轮次静态对话；一次只提出一个具体问题，无自动打字等待 |
| 元件主要是技术台上的方块 | 还未形成道具与职业工作的联系 | 工具箱查看：光敏模块、LED、开发板的用途与手册入口；不从插画取引脚或器件参数 |
| 点击动作与反馈不在同一语境 | 行动后不容易判断发生了什么 | 场景热点高亮、持续可读的状态消息、打开/关闭面板与焦点返回 |
| 旧 C 客户测试占位在“尚未运行”时显示大勾 | 容易误读为已通过 | 改为中性观察图标；该问题仅针对 C 旧预览，不代表 E 当前主入口 |

三处探索都有同名按钮列表，支持键盘，不要求逐个点完。可以直接打开工程工具。查看邮件、对话、物品和手册均不推进课程、不授予通过、不入账。用户不用先理解探索规则才能开始真实工作。

## 动效边界

- 入场淡入 600ms，轻微缩放 1.012→1；不持续移动摄像机。
- 热点柔和光圈仅运行两轮；hover 位移 3px；对话文字淡入 180ms，不逐字阻塞阅读。
- 提供“减少动效”，同时遵守系统 `prefers-reduced-motion`；没有自动播放声音、闪屏、倒计时或随机环境干扰。
- 状态消息不自动消失，弹窗使用原生 dialog；串联对话→邮件、物品→手册后仍返回最初入口焦点。

## 与 D / E 的实际协调

D 给出唯一目标、三处可跳过探索、每轮一个问题以及不做集邮通关的约束。E 确认现有主入口已接入真实软件闭环，C 不重建模块。两线同意使用中性故事标题“校园自动灯委托”；阅读角继续作校园场景插画，不改变 D 已冻结的需求或测试版本。

C 采用 E 的 `onAction(actionId)`、`actionStates` 与 `goal` 协议。D 新提的展示 ID 显式映射为：

| D 展示候选 | E / C 实际动作 |
|---|---|
| `open_order_mail` | `open_mail` |
| `talk_requirements_npc` | `talk_requirements_npc` |
| `inspect_starter_kit` | `inspect_kit` |
| `open_manual_section` | `open_manual`，具体节号由 E 按课程内容映射 |

上述动作均为打开或查看。提交、运行测试、入账和教师签核不属于此协议。E 在导航目标处验证实际前置条件；UI 的禁用样式不能替代业务校验。

## 验证与实际限制

`verify-adventure.mjs` 覆盖场景与同名列表、键盘打开入口、静态对话、物品与手册、串联弹窗焦点返回、所有探索后受控目标保持不变、禁用原因、工具/求助无业务副作用、390px 布局、手动及系统减少动效、叠加当前工作区旧全局样式后的桌面宽度。四张截图来自浏览器实际页面，另复跑旧 UI 验证与五张素材加载。

独立入口：`/src/ui/adventure-preview.html`。这是视觉/交互小样，未接 E 的实际业务状态，不能用本分支证明已在主流程集成、实际通关或形成 ARPG 试玩体验。未做真实学生测试、屏幕阅读器实机测试、声音或设备性能矩阵验证。

## 后续优先级

1. **P0 接入已有流程**：由 E 把真实 `goal`、可用动作和版本提示传入工位探索壳；保留直达实际编辑工具的路径。不要用故事对话替换需求提交或实际测试。
2. **P1 行动—现象—推理—作品证据**：在实际运行结果到达后，让灯的表现、执行步骤和错误位置一起反馈。没有运行证据时保持等待态。成功动效须绑定确切版本的真实软件结果，并与教师实物验收区分。
3. **P1 更清晰的接续**：关闭工具后回到原位置，目标句指向刚产生的具体问题；修改接线/代码后显示证据过期，而不是保留成功装饰。
4. **P2 试玩校准**：记录初学者能否找到入口、理解下一步、跳过探索、读懂失败原因，再决定是否增加环境细节、角色表情或可选音效。没有证据前不增加移动、战斗、3D 或更多必点对象。
