## A　基础订单 1.0.0：完整可执行短代码

下面是**供本项目解释器执行的完整简写 C++**。逻辑对应学生手动搭建的积木；不是可直接交给 Arduino IDE 的完整 `.ino`。在当前网页里，应先由自己的积木通过基础客户测试，再点“保存积木快照，查看代码变更 →”获得文本入口，不能用粘贴答案跳过积木阶段。

可单独保存的同内容文件：[基础自动灯.short.cpp](examples/基础自动灯.short.cpp)。

```cpp
const int threshold = 450;
int light = 0;

void setup() {
}

void loop() {
  light = readAnalog(LIGHT);
  if (light < threshold) {
    writeDigital(LAMP, true);
  } else {
    writeDigital(LAMP, false);
  }
  waitMs(100);
}
```

检查顺序：

1. 只给 `threshold` 一个初值 450，程序运行中不改它。
2. 每次进入 `loop()` 都重新读取 `LIGHT`，存入 `light`。
3. 449 条件为真，写亮；450 条件为假，写灭；两个分支都写明确状态。
4. 等 100 ms 后重跑整段 `loop()`，不是从 `if` 中间继续。
5. 空 `setup()` 合法；设备初始输出由运行配置设置为 false，这不替代 `loop()` 里明确关灯。

预计基础套件 26 条断言全部通过。把同一程序拿去验证变更需求 1.1.0，应失败，因为 500 仍会灭；**它没有同时满足两个互相不同的需求版本。**

## B　客户变更 1.1.0：完整可执行短代码

唯一需求改动是声明里的 `450 → 600`。仍然使用严格 `<`，硬件与等待不变。

可单独保存的同内容文件：[变更自动灯.short.cpp](examples/变更自动灯.short.cpp)。

```cpp
const int threshold = 600;
int light = 0;

void setup() {
}

void loop() {
  light = readAnalog(LIGHT);
  if (light < threshold) {
    writeDigital(LAMP, true);
  } else {
    writeDigital(LAMP, false);
  }
  waitMs(100);
}
```

预计变更套件 20 条断言全部通过：500 与 599 应亮，600 与 601 应灭。主线仍需当前变更情境与本人积木映射；可点“检查当前代码”，再运行变更客户测试。复制完整实现不会补齐这些过程记录，也不证明已经理解。

## C　看懂一段动态运行

基础程序，输入依次在 0 ms 为 150、575 ms 变 850、1135 ms 变 200：

| 时刻 | 输入与程序行为 | 灯 |
|---|---|---|
| 0 ms | 读到 150，比较成立，写 true，开始等 100 ms | 亮 |
| 100～500 ms，每隔 100 ms | 重新读取 150，并明确写 true | 保持亮 |
| 575 ms | 输入变为 850，程序还在等待 | 暂时保持亮 |
| 600 ms | 等待结束，读 850，比较不成立，写 false | 灭 |
| 775 ms | 客户检查变化后 200 ms 时的状态 | 应灭 |
| 1135 ms | 输入变为 200，程序还在等待 | 暂时保持灭 |
| 1200 ms | 重新读到 200，写 true | 亮 |
| 1335 ms | 客户检查变化后 200 ms 时的状态 | 应亮 |

这个过程解释的是执行器的虚拟时间模型，不声称真实板卡每次调用没有开销。完整客户断言见[§09.1](工程参考.md#s091)。

## D　有意写错的局部片段，不要当完整程序运行

先预测每种错误会被哪类测试发现，再返回自己的程序检查。

```text
if (light <= threshold)       // 错在边界包含“等于”
readAnalog(light)             // 错在把变量名当成端口
writeDigital(LAMP, 1);        // 错在用整数代替布尔值
threshold = 600;              // 对 const 常量做运行时赋值
waitMs(0);                   // 合法但不推进时间，循环可能耗尽预算
```

读取只放在 `setup`、省掉 `else` 中关灯、把 `waitMs(100)` 放到唯一一个分支里，也都需要重新检查动态行为。不要把出现的第一个错误提示当作程序唯一问题。
