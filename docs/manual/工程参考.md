## §01.2　先断电，再接线

本课只涉及低压 LED 演示，不接家庭市电、不改装照明电器。实物接线必须断电，教师核对后才允许上电。闻到异味、明显发热或出现异常时停止操作并叫教师，不要靠反复插拔试错。

网页检查的是有限连接关系，不算电压、电流、发热、绝缘、模块接反后的损坏。详情与教师记录表在[教师实物附录](教师实物附录.md)。

## §02.1　把客户的话拆成可检查的行为

一张需求至少回答四件事：读什么、怎样判断、两种情况分别做什么、以后还会不会再读。还需给出可检查的时限和边界。

本单基础规则为 `light < 450 → lamp=true`，其余 `lamp=false`，变化后不超过 200 ms。英文小写是课程数据的信号名，代码端口的拼写查[§03.1](#s031)。

基础版用六个顺序情境核对这些行为，变更版再核对四个新情境。当前只显示一道题，答错或求助会给对应小观察，随后重试。旧四项卡片、解释字数或点击林工下一句均不放行。自由原话不做任意语义评分；有限明确求助句只转引导，未知文字不参与自动判对。NPC不是在线AI，也不能替代客观测试或教师安全批准。

## §03.1　输入、处理、输出与三层名字

```text
虚拟光照滑条或客户输入序列
          ↓ 输入
光照模块 AO ── Uno A0 ── readAnalog(LIGHT) ── 变量 light
          ↓ 处理
                    light < threshold
          ↓ 输出
             writeDigital(LAMP, true/false)
          ↓
Uno D9 ── 电阻 ── LED ── GND
```

| 所处层 | 光照 | 灯 | 你在哪里看到 |
|---|---|---|---|
| 课程数据 | `light` | `lamp` | 需求文件、客户测试、结果适配 |
| **程序逻辑端口** | **`LIGHT`** | **`LAMP`** | 积木端口下拉、短代码函数参数 |
| 虚拟物理引脚 | `A0` | `D9` | 接线台，生成器内部输出引脚号为 `9` |
| 你声明的变量 | 本册命名 `light` | 不必另设 | 变量声明、赋值、判断 |

适配器负责课程 `light/lamp` 与程序 `LIGHT/LAMP` 的转换。端口大小写必须准确。`readAnalog(light)` 不会读到名为 `light` 的变量；它把 `light` 当成一个未知端口。`readAnalog(A0)` 和 `writeDigital(9,true)` 也不是本编辑器允许的设备用法。

光照读数为整数 0～1023，低值表示暗，仅为虚拟约定；输出为布尔值，`true` 亮、`false` 灭。不要把 0～1023 当作电压值、百分比或 lux。

## §04.1　开发板与引脚速查

当前设备属于 Arduino Uno 家族，虚拟图参考 Uno R3/A000066 的端子名称。实物代际、芯片、FQBN（编译器识别具体板型的标识）均未定。

| 画面端子 | 内部完整名称 | 本单用途 | 与谁相连 |
|---|---|---|---|
| `5V` | `uno:5V` | 候选电源连接 | 模块 VCC |
| 上排 `GND` | `uno:GND_TOP` | 公共地，可代替另外两处 GND | 模块 GND 或 LED K |
| 下排第一处 `GND` | `uno:GND_1` | 本册用于模块公共地 | 模块 GND |
| 下排第二处 `GND` | `uno:GND_2` | 本册用于 LED 回路 | LED K |
| `A0` | `uno:A0` | 本单模拟输入，绑定 `LIGHT` | 模块 AO |
| `D9` | `uno:D9` | 本单数字输出，绑定 `LAMP` | 限流电阻 |
| `A1` | `uno:A1` | 可选中，但不是本单输入口 | 接 AO 会报错 |
| `D8` | `uno:D8` | 可选中，但不是本单输出口 | 接灯会报错 |
| 其它灰色端子 | 依标签 | 此关仅可查资料，不开放连线 | 不使用 |

上、下排和相对位置只帮助找端子，不能代替读字。选中端子后，资料区显示完整名称，可以区分三个 `GND`。三个 GND 在虚拟模型中板内相连，没必要额外互接。

实际 Uno 其它 IO 也可能可用，但“实物能用”和“符合这单指定映射”是不同条件。本单没有按钮数字输入、PWM 调光或模拟输出。

<a id="s051"></a>
## §05.1　光照模块资料

| 端子 | 是什么 | 常见混淆 |
|---|---|---|
| `VCC` | 模块供电端 | 不能拿 AO 代替供电 |
| `GND` | 与板卡共用的参考地 | 不能省略，也不是 `5V` |
| `AO` | Analog Output，模拟信号输出 | `O` 是字母，不是板上 A0 的数字 0 |

模型中的完整名称为 `sensor:VCC`、`sensor:GND`、`sensor:AO`。这里只有 AO 模块，没有本单可用的 DO 接口。实物模块若多出 `DO` 或端子顺序不同，不可凭外形照抄图；由教师核对厂商资料和实测方向。

真实亮暗读数可能与本模拟约定相反，也可能受位置、遮挡、供电或器件变化影响。450/600 不能直接迁移为现实“暗”的标准。

<a id="s052"></a>
## §05.2　LED 与限流元件

LED 的 `A` 为阳极（画面 `A +`），`K` 为阴极（画面 `K −`）。本关路径固定为：**D9 → 电阻 → A → LED → K → GND**。灯不是没有方向的电阻。

电阻两个端子 `resistor:1`、`resistor:2` 可以交换；只要电阻确实串联在 D9 与 LED A 之间。导线绕过电阻会形成旁路，不算限流。不要把示意图里电阻两端视为内部短接。

本检查器暂不支持“电阻串在 LED 负极侧”的等效物理布置。这是课程规则范围，不是在声称所有其它串联位置都违反物理规律。

界面的 **220 Ω 是候选值**，不是已核准实物阻值；代码里的电流参考也未参与仿真。需要的实际阻值、功率、LED 电流与供电兼容性见[教师实物附录](教师实物附录.md)。

## §06.1　读图、连线与网络

完整操作在[首单手册第 2 节](首单手册.md#t2)，原创图见[六线功能图](assets/首单虚拟接线.svg)。

检查器关心端子属于哪张电气网络，不关心线在屏幕上绕哪条路、起点终点写在哪一侧。拖元件标题移动只改变布局；看起来交叉的线不会自动相接，导线只能由两个指定端子组成。

| 网络 | 本册端点 |
|---|---|
| 模块电源 | `uno:5V ↔ sensor:VCC` |
| 公共地 | `uno:GND_1 ↔ sensor:GND`；`led:K ↔ uno:GND_2`；三个板内 GND 相通 |
| 光照输入 | `sensor:AO ↔ uno:A0` |
| 灯输出到电阻前端 | `uno:D9 ↔ resistor:1` |
| 电阻后端到 LED | `resistor:2 ↔ led:A` |

检查时展开“连接清单”看完整端点，点击行内“删除”移除错误线；画布线本身不提供删除按钮。空白四件套只有“待连接”提示，接上部分线后才逐项显示缺失连接。错误卡能定位端子，不能自动修复。

<a id="s062"></a>
## §06.2　引导点灯不等于自动灯

完成接线后，在积木工具当前一步点“让虚拟 LED 亮起来”或“让虚拟 LED 熄灭”。执行器运行隔离的输出引导程序，把实际写入留在“上一次实际操作”中；它不会把自动灯答案填进学生积木。

这是一项输出观察，**不能通过基础客户测试**，也不能直接解锁代码变更。随后仍要从空白搭建读取、比较、两个分支和等待，并逐项观察。想亲手验证最小输出程序时，可在持续执行连接“数字输出 LAMP 设为 true”和“等待 100”；它在明处也亮，不是完整自动灯。

当前短代码入口要先通过基础积木测试才能由页面生成，所以不要尝试在接线阶段寻找一个可以粘贴 `.cpp` 的运行框。

## §07.1　循环、读取、等待和状态

| 机制 | 当前语义 | 对自动灯的影响 |
|---|---|---|
| 全局变量 | 初始化一次，随后跨轮保留 | 不重新赋值就还是旧读数 |
| 启动时 / `setup()` | 每个独立场景开始时一次 | 不适合放唯一一次光照读取 |
| 持续执行 / `loop()` | 整段不断重跑 | 本单不必再包 `while(true)` |
| `readAnalog(LIGHT)` | 执行到这里才采样 | 必须放在每轮判断之前 |
| `writeDigital` | 写后保持，直到下一次写 | 没有关灯动作就可能一直亮 |
| `waitMs(N)` | 暂停本程序 N ms，变量与输出保持 | 输入变化可以发生，但要等恢复后重新读取 |
| 普通计算 | 虚拟耗时为 0 | 并非真实 CPU/ADC 耗时模型 |

例：程序每 100 ms 读取一次，输入在 575 ms 变亮。最近两次采样在 500、600 ms，程序在 600 ms 发现变化并关灯，响应间隔 25 ms。客户在 775 ms 检查结果，并在下一次变化前再次检查保持状态。

如果把等待改成 250 ms，同一变化要到 750 ms 才采样，某些变化可能刚好满足而另一些会超时。必须对全部固定场景测试，不能因为一次没超时就认定总是合格。

`waitMs(0)` 合法，但不会推进虚拟时间；无等待的循环可能在同一毫秒重复直到 `STEP_BUDGET`。这不是“已经永远运行成功”，而是模拟没覆盖客户窗口。

执行上限：最多 100000 步、60000 ms；客户场景各有更小预算。达到观察窗口时状态 `completed` 只表示该窗口完整执行，不表示 `loop()` 从此终止。步数超限或运行错误都不能算客户通过。

<a id="s072"></a>
## §07.2　严格比较与两个分支

| 输入 | `light < 450` | 基础灯状态 | `light < 600` | 新版灯状态 |
|---|---|---|---|---|
| 449 | 真 | 亮 | 真 | 亮 |
| 450 | 假 | 灭 | 真 | 亮 |
| 500 | 假 | 灭 | 真 | 亮 |
| 599 | 假 | 灭 | 真 | 亮 |
| 600 | 假 | 灭 | 假 | 灭 |
| 601 | 假 | 灭 | 假 | 灭 |

`<` 不包含相等，`<=` 包含相等。后者会导致 450 或 600 的边界错误。`=` 是赋值，不是比较；判断是否相等写 `==`。

`if` 中的动作只在条件真时发生，`else` 中的动作在假时发生。程序不会因为进入假分支就自动撤销过去的 `true` 输出，必须明确写入 `false`。

## §08.1　简写 C++ 速查

本编辑器接受**受限的 C++ 结构和固定教学函数**，不是任意 Arduino 草图。它先解析为确定的程序结构，再由固定规则生成真实 Arduino C++，不通过模型翻译，也不执行任意字符串代码。

### 文件骨架

```cpp
// 全局声明，放在两个函数前；必须有字面量初值
int count = 0;
bool ready = false;
void setup() {
  // 可省略整个 setup；保留时只能在 loop 前
}
void loop() {
  count = count + 1;
  waitMs(100);
}
```

这个片段仅解释结构，不是自动灯答案；长期运行可能整数溢出。完整订单示例在[参考实现](参考实现.md)。

### 名字、类型与声明

| 条目 | 允许 | 不允许或注意 |
|---|---|---|
| 名字 | 英文字母开头，后接字母、数字、下划线，总长 1～32 | 中文名、以数字或下划线开头、重复名、关键字、与 `LIGHT/LAMP` 同名 |
| 整数 | `int light = 0;`，范围 −32768～32767 | 小数、十六进制、科学计数法、超范围值 |
| 布尔 | `bool enabled = false;` | `bool enabled = 1;` 不自动转换 |
| 常量 | `const int threshold = 450;` | 运行时 `threshold = 600;` 不合法；客户变更应改声明源码再解析 |
| 初值 | `0`、`-1`、`true` 等字面量 | `int light = readAnalog(LIGHT);`、`int x = 1 + 2;` |
| 声明位置 | 只允许全局，且必须在函数前 | 不支持函数内局部声明或作用域遮蔽 |

所有名称区分大小写。赋值、函数调用、声明末尾要有英文分号 `;`。全角括号、全角分号、中文引号不能代替代码符号。注释支持 `// 到行尾` 与 `/* 跨行 */`。

### 固定函数与端口

| 调用 | 参数与结果 | 首单可用性 |
|---|---|---|
| `readAnalog(LIGHT)` | 读整数输入，0～1023 | 可用；返回值可赋给 `light` |
| `writeDigital(LAMP, true)` | 第二参数为布尔表达式；写亮 | 可用；`false` 写灭 |
| `waitMs(100)` | 整数毫秒，单次 0～32767 | 可用；负值错误；0 不推进时间 |
| `readDigital(PORT)` | 语言支持读布尔输入 | **本单没有数字输入端口，也没有相应读取积木，不能写 BUTTON** |

`HIGH/LOW` 可作为 `true/false` 的布尔字面量别名。推荐初学者统一用 `true/false`，避免把电平和数值混写。`pinMode`、`analogRead`、`digitalWrite`、`delay` 是完整 Arduino 层 API，不是本短代码编辑区允许直接调用的函数。

### 控制结构

| 结构 | 例子 | 限制 |
|---|---|---|
| 条件 | `if (light < threshold) { ... } else { ... }` | 条件必须是 bool，两个语句体使用花括号；`else` 可省略但自动灯需要关灯路径 |
| 嵌套 | 在任一分支中继续放 `if` | 文本支持 `else if`；积木用“否则”内嵌另一个如果，不新增 IF1 分支 |
| 条件循环 | `while (ready) { waitMs(100); }` | 不自动更新 ready，须设计退出或持续推进时间；本单不需要 |
| 赋值 | `light = readAnalog(LIGHT);` | 目标须已声明且不是常量，类型相同 |

不支持 `for`、`do/while`、`switch`、`break`、`continue`、`return`、`++/--`、`+=`、三元表达式、数组、字符串、指针、引用、用户函数、库、递归、动态内存、系统调用、`#include`。不能在 `loop` 后再追加函数。

### 运算与优先级

从高到低。拿不准就加括号，不靠猜测。

| 顺序 | 运算符 | 输入 → 结果 |
|---|---|---|
| 1 | `( )`、函数读取 | 括号内先算 |
| 2 | 一元 `-`、`!` | int → int；bool → bool |
| 3 | `* / %` | int、int → int |
| 4 | `+ -` | int、int → int |
| 5 | `< <= > >=` | int、int → bool |
| 6 | `== !=` | 同一类型的两值 → bool |
| 7 | `&&` | bool、bool → bool，左假则不计算右边 |
| 8 | `||` | bool、bool → bool，左真则不计算右边 |

同级二元运算从左到右；除法向零截断，如 `-7 / 2` 为 `-3`，余数 `-7 % 2` 为 `-1`。运算中溢出、除数为 0 会报错，不是静默绕回。`if (1)` 不合法；`if (light < threshold)` 合法。当前算术积木不提供 `%`，也不支持幂运算，不能把语言支持范围等同于工具箱范围。

### 编辑与执行边界

最多 24000 字符、5000 词法 token、1000 程序节点、64 个全局变量、32 层嵌套。本单远不需要接近这些上限。解析成功仍需检查设备端口和客户行为；例如语言层可以认出 `readAnalog(OTHER)`，实际设备检查仍会拒绝未知端口。

从积木生成代码时会自动加一些括号和空 `setup()`，不影响含义。短代码可编辑，但不能自动完整反转为积木。当前工具箱只支持一个入口，全部动作与值必须接入它；停用、散落、缺值积木都报错。

<a id="s082"></a>
## §08.2　解析、测试、生成、编译、上传不是一回事

| 证据 | 证明什么 | 不证明什么 |
|---|---|---|
| 检查当前代码 | 短代码符合语言结构与语义约束 | 学习完成、客户全部行为或实物安全 |
| 客户测试通过 | 当前快照满足固定虚拟场景与时刻断言 | 所有可能输入、真实时间、电气性能 |
| 导出候选 `.ino` | 当前程序已由固定生成器展开为源码 | 目标板 core/FQBN 已选对、编译或上传成功 |
| 目标板编译 | 后续在指定工具链可构建 | 传到了指定板或实物功能正确 |
| 上传完成 | 后续工具报告传输完成 | LED 正确响应或教师验收通过 |
| 教师现场验收 | 当前实物及版本按记录完成检查 | 另一版本或另一块硬件也通过 |

完整生成源码会插入固定运行库、引脚模式、初始输出、受限整数检查，并使用 `int16_t` 保持 −32768～32767 的范围。它可能比短代码长很多，不是学生需要照抄的部分。执行错误时运行库保持输出并停止正常程序直到复位；这不是电气保护，也不等于硬件看门狗。目标板编译与上传目前未接入。

<a id="s091"></a>
## §09.1　客户测试：明暗、边界与往返

客户测试每个场景从新状态开始。输入会保持到下一帧；同毫秒输入先变，程序再采样。输出保持到下一次明确写入。客户在变化后 200 ms 和下一次变化前检查。断言只采固定时刻，不代表验证所有瞬态。

### 基础套件 1.0.0，26 条断言

以下“输入时刻→值”中的时刻单位均为 ms。“检查时刻：输出”是固定客户预期，不从你的代码生成。

| 场景 | 输入时刻 → 值 | 检查时刻：输出 |
|---|---|---|
| 全暗与稳定暗处 | 0→0；600→150 | 200、599、800、1199：亮 |
| 全亮与稳定亮处 | 0→1023；600→850 | 200、599、800、1199：灭 |
| 449、450、451 的边界 | 0→449；600→450；1200→451；1800→449 | 200、599：亮；800、1199、1400、1799：灭；2000、2399：亮 |
| 暗亮往返与重新读取 | 0→150；575→850；1135→200；1715→900；2305→150 | 200、574：亮；775、1134：灭；1335、1714：亮；1915、2304：灭；2505、2899：亮 |

### 变更套件 1.1.0，20 条断言

| 场景 | 输入时刻 → 值 | 检查时刻：输出 |
|---|---|---|
| 原有暗亮功能继续工作 | 0→0；600→1023；1200→150 | 200、599：亮；800、1199：灭；1400、1799：亮 |
| 新旧需求区别：500 应亮 | 0→500；575→850；1135→500 | 200、574：亮；775、1134：灭；1335、1699：亮 |
| 599、600、601 的新边界 | 0→599；600→600；1200→601；1800→599 | 200、599：亮；800、1199、1400、1799：灭；2000、2399：亮 |

### 读结果和轨迹

先检查需求与测试集版本，再读第一条失败行：输入是什么，时刻是什么，期望与实际怎样不同。如果实际为“无有效输出”，先查运行是否出错、是否有明确写入，不要把缺数据当成灭灯。

“04 客户测试”能展开全部场景的输入/固定断言；轨迹滑条目前只显示首场景。常见事件：`read` 采样、`assign` 赋值、`branch` 判断、`write` 输出、`wait` 等待、`resume` 恢复、`cycle` 新一轮、`stop` 观察结束或报错。多个事件可以同在 0 ms，这是虚拟计算耗时为 0 的模型，不是时间轴坏了。

滑条上“第几步”不是毫秒，也不是唯一事件编号。看一个场景的轨迹不能代替整套测试。接线页手动滑条每次独立观察 0～100 ms，尤其不能证明“从暗变亮后之前的灯被关掉”。

<a id="s092"></a>
## §09.2　一次只验证一个排错假设

先保留现象，查下面最贴近的一行。修正后重新运行同一版本的整套测试，不修改客户断言。

### 接线故障

| 提示码或现象 | 优先检查 | 动作与资料 |
|---|---|---|
| `SENSOR_POWER_MISSING` | 5V 到 VCC 是否缺线 | 展开清单核对 [§05.1](#s051) |
| `SENSOR_GROUND_MISSING` | 模块 GND 是否接到板 GND | 不要接到电源；[§04.1](#s041) |
| `SENSOR_PIN_MISMATCH` / `UNMAPPED_PIN` | AO→A1 或灯→D8 | 删除错线，改为 A0/D9 |
| `LED_GROUND_MISSING` | LED K 到 GND 是否缺失 | 核对 LED K 而非 A |
| `LED_POLARITY_REVERSED` | LED A/K 是否交换 | 按标记恢复方向；[§05.2](#s052) |
| `LED_SERIES_RESISTOR_MISSING` | D9 与 A 之间是否经过电阻 | 补全两段线，不直接连接 |
| `RESISTOR_BYPASSED` | 有无跨过电阻的额外导线 | 删除旁路线，不能只添加电阻 |
| `POWER_SHORT` / `NET_CONFLICT` | 5V/GND 或不应合并的网络相连 | 立即核对清单；实物保持断电 |
| `DEVICE_PROFILE_MISMATCH` | 旧草稿设备版本不同 | 请教师/维护者处理，不能修改版本号骗过检查 |
| 规则通过但仍有黄色实物警告 | 当前就是候选硬件 | 保留警告，它不阻止虚拟编程 |

### 积木与短代码故障

| 提示码或现象 | 原因候选 | 只做这一项检查 |
|---|---|---|
| `BLOCK_ROOT` | 多入口或散落块 | 留一个入口，把备用块移除 |
| `BLOCK_INPUT` | 数字、布尔或条件槽空着 | 查看提示槽名，补入对应值 |
| `DISABLED_BLOCK` | 停用块仍留在作品 | 启用或移除，不靠停用藏答案 |
| `UNKNOWN_VARIABLE` | 名字不一致或没声明 | 对比 `light/Light`、`threshold` 拼写 |
| `TYPE_MISMATCH` | 布尔位置用了 0/1、数字位置用了真/假 | 核对两种类型，见 [§08.1](#s081) |
| `CONSTANT_WRITE` | 对常量运行时赋值 | 修改声明源码而不是写赋值语句 |
| `PORT_MAPPING` | 写错端口或方向 | 只用读 `LIGHT`、写 `LAMP` |
| `SYNTAX` / `UNKNOWN_TOKEN` | 缺英文分号、花括号、使用未支持语法 | 从错误所需符号检查，不整篇重写 |
| `INTEGER_RANGE` / `DIVIDE_BY_ZERO` | 整数溢出或除零 | 查运算值，不能当警告忽略 |
| `WAIT_RANGE` | 等待出现负数 | 检查等待表达式；[§07.1](#s071) |
| `STEP_BUDGET` | 无等待循环、0 等待或过多计算 | 让时间推进，避免不退出的内层循环 |
| 当前代码无法检查或运行 | 语法、变量或端口不合法 | 查看具体诊断，检查当前确切文本，再运行同版测试 |

### 客户行为与流程故障

| 现象 | 先查哪里 |
|---|---|
| 449 正常但 450 错 | `<` 是否误选 `<=`；不要先改接线 |
| 暗处亮，亮处也一直亮 | `else` 是否写 `false`；是否每轮读取 |
| 一开始亮/灭正确，之后不再变 | 读取是否只在 `setup` 中；判断是否用旧变量 |
| 方向全反 | 比较方向或 true/false 是否交换 |
| 稳定场景过，往返超时 | 等待时间、读取位置、只在单分支等待 |
| 新版 500 不亮 | 是否仍为 450；是否保存当前确切文本并运行 1.1.0 |
| 手动观察没问题，客户测试失败 | 静态观察不能证明动态行为；查看具体失败行 |
| 灯显示未运行 | 先核对接线，然后积木/代码是否合法，观察是否正常结束 |
| 基础测试或生成代码按钮灰色 | 当前需求情境、接线、逐步观察和基础测试哪些仍未就绪；先看当前目标 |
| 已改代码但当前结果消失 | 旧报告仍在历史，确切文本改变需重新测试；比较映射不因随后改数字而自动丢失 |
| 恢复或保存有问题 | 查看本机存储状态，保留页面并导出；不要新建身份覆盖旧记录，见 [§01.1](#s011) |

先填[学生排错记录](首单手册.md#t7)再求助，带上错误和版本。页面求助目前不发送消息，需要直接请教师来查看。

## §10.2　实物功能验收
