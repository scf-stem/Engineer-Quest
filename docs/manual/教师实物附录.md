# 教师实物附录：冻结规格后再上电

**当前状态：软件教学路径可查，实物方案尚未核验。** 本附录是教师准备与记录清单，不是已签发的上电许可，也不是采购 BOM。

## 1　当前已知与未知分开

| 项目 | 虚拟课堂已知 | 实物还缺什么 |
|---|---|---|
| 板卡 | Arduino Uno 家族；图参考 R3/A000066 | 确切代际、型号、兼容板批次、主控、USB 接口/桥接芯片 |
| 编译目标 | 生成 Arduino C++，要求 C++11，固定运行库 `eq-runtime/0.1` | 正确 FQBN、板卡 core 及版本、工具链、可重复编译记录 |
| 信号映射 | LIGHT→A0；LAMP→D9，输出参数为 9 | 确认实物板相应端子与可承受电气条件 |
| 输入 | AO 模块，合成 0～1023，低暗高亮 | 型号、供电范围、输出范围、引脚顺序、实际亮暗方向、现场读数 |
| LED | A/K 极性，数字开关，串联电阻 | LED 规格、正向压降、允许电流、所需限流值及功率 |
| 电阻 | 界面 220 Ω，仅候选 | 经审核的实际阻值与功率；不能因界面有数就冻结 |
| 电源 | 虚拟 5V 端子 | 实际供电方式、极性、板卡/模块兼容性和电流预算 |
| 接线 | 六线功能关系，没有面包板导通模型 | 面包板电源轨断点、孔列导通、跳线端点、短路/松动检查 |
| 阈值 | 基础 450，变更 600 | 实测校准与实物验收规则，不能直接照搬 |
| 上传 | 当前没有实现 | 工具、串口识别、驱动、权限、版本绑定及失败处置 |

仓库中的 `resistorOhms: 220` 标为 `candidate`；`maximumIoCurrentMa: 20` 标为 `reference-only-not-simulated`。两者都没有形成对具体实物的安全结论。不要把这两个数字印成通用元件额定规格。

## 2　实物课之前应准备的资料包

- [ ] 板卡正反面照片、确切产品型号与官方资料，确认针脚名称和电气条件。
- [ ] 光照模块产品资料，确认 `VCC/GND/AO` 顺序、工作电压和输出范围。
- [ ] LED 规格及极性识别方法，不仅依赖引脚长短，因为引脚可能已剪过。
- [ ] 限流设计记录：按输出电平、LED 正向压降、目标工作电流计算，并核对输出能力、阻值/功率及允差。不要只使用典型压降而忽略最不利条件。
- [ ] 实际面包板布置图，明确孔列、电源轨分段、公共地与禁止直连路径。
- [ ] 与板型匹配的 FQBN、core/工具链版本，独立的目标编译日志。
- [ ] 上传工具与端口确认流程，出错时如何断电/停止，而不是连续重试未知设备。
- [ ] 与虚拟需求对应但已校准的实物任务卡、响应测量方法、可接受结果范围。

本册不替代以上资料，也不提供待猜的实际阻值。仅为帮助理解，限流电阻计算需要知道“电阻两端电压”和“目标电流”，但最终取值与额定功率须教师依据实际元件和板卡资料确认。

## 3　断电检查与首次上电

1. 识别学生作品版本，核对短代码、导出 `.ino`、需求版本、接线版本与板卡，不用其它同学的成功记录替代。
2. 所有电源断开后，按实际端子而非示意图外形接线。
3. 教师检查模块供电/地/信号，LED 极性，串联电阻和无旁路，板卡 IO 与供电条件，面包板导通关系，是否有松线或短路。
4. 只有教师确认实际电路可上电后再进行下一步。网页“接线规则通过”、NPC 回复或代码解析均不构成此确认。
5. 确认工具链目标，对**这份确切源码**编译；编译记录与上传记录分开保存。上传前再次核对目标端口，避免写入不相关设备。
6. 上电后按已批准的观察方式确认电气状态。如异常，停止操作并按教师安全流程处理；软件中等待或死循环没有电气保护作用。

目前应用只显示上述后续流程，没有实现在线签核、编译或上传。不要向学生承诺点击页面某个按钮就能完成烧录。

## 4　先校准，再做实物功能测试

## 6　课堂使用边界

采用本机浏览器时，一人一份独立档案或由教师明确管理草稿，避免同一存储被多名学生共用。当前没有真实账户、线上教师队列、云同步和真实排名权限。使用示例或教师帮助应记录支持来源，不羞辱求助，也不把照着答案完成和独立排错混为同一证据。

本稿尚无真实学生完整试用记录，不承诺固定课时。先安排小范围走读：新学生能否认出端子、从空白接上积木、读懂第一条失败、独立完成 450→600 的变更；把卡点记录反馈给后续 UI/NPC 重构。
