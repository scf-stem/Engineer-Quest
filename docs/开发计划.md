## 3. 产品主线与每步成果

1. **入职**：上课发纸质手册、讲公司与客户背景；网站领取个人员工身份。成果：员工证、个人工位、课程/手册版本；不设小队。
2. **中文需求评审**：点击 NPC 接单，用中文说明输入、判断、输出及持续工作方式；选择方案并解释。成果：需求卡，不要求先会代码。
3. **工程准备与二次审核**：查手册认识 IO、元件与安全规则，在图形工作台接线并完成引导点灯。成果：接线方案和设计检查，不重复完整编程关。
4. **图形化 Demo**：学生为同一套硬件搭建读取、判断、输出和循环逻辑，改变虚拟光照观察结果。成果：可运行原型、测试证据及 NPC 方案讨论。
5. **轻代码变更**：展示学生积木对应的代码，客户提出一个小变更，学生读懂并修改后复测。成果：可解释、可编译的确切代码版本。
6. **真机交付**：断电接线，教师安全确认后上电与烧录；学生测试和排错，教师验收版本。成果：真实交付凭证，不用网页点击冒充。
7. **进阶订单与商城**：基础完成的学生个人领取工程币，选审核模块做升级；失败可重试，不阻碍基础结业。
8. **展示和职业回顾**：说清完成的功能、一次排错与喜欢的岗位工作；兴趣是学生自述，不由 AI 输出职业适配结论。

网站回答“现在做什么”；纸质/电子手册回答“依据什么知识和规则做”。两版手册共用节号和版本。教师负责走访、节点跟进、安全和验收，NPC 不取代实物安全责任。

## 4. 五条开发工作线

### A. 编程系统：积木、轻代码与运行引擎

- 继续利用《深圳 I/O》研究结果，借鉴查手册、少量指令、测试和排错体验，不照搬角色、语言或素材。
- 负责积木、文本编辑、统一程序结构、解析/类型与语义检查、解释执行、代码生成、映射和一致性测试。
- 当前边界：`src/engine.js`、`src/blocks.js` 和引擎测试；下一步先提取明确接口，再逐步拆模块。
- 交付：可组合语言小样、语法速查、错误示例、执行轨迹、测试和已知限制。
- 不自行改设备引脚标准、客户通过条件或游戏奖励。

### B. 电子工作台：虚拟接线、元件与真机链

- 负责板卡/元件模型、端子与引脚规范、拖拽接线、连接校验、虚拟传感器和输出反馈、源码与接线导出及实机验证。
- 首期为有限元件的逻辑仿真，不承诺通用 Arduino 或电路物理模拟。
- 交付：准确端子图、合法/非法接线样例、校准记录、目标机编译烧录记录和教师检查表。
- 与 A 共用 pin map、输入输出和时间语义，不另造一份仿真程序。

### C. 视觉与界面：原创游戏画面和 UI

- 负责原创公司/NPC/办公室/工位/邮件/员工证/商城的整体视觉、界面组件和可访问交互。
- 按用户偏好优先使用 Image 2 制作人物、场景、道具等插画；开始产图前核实工具实际可用模型，不能把其他模型产物声称为 Image 2。
- 引脚、接线、代码、中文标签和按钮使用可核验 SVG/HTML/Canvas 等，不以生成图片保证技术准确性。
- 先做一张工位风格稿和一套组件规范，经风格确认后批量资产；保留来源、许可、版本和尺寸清单。
- B 负责硬件准确性与运行，C 负责统一外观；不要把功能画布做成静态背景图。

### D. 游戏与课程：订单、NPC、手册及教学节奏

- 负责公司和客户设定、首单、需求评审问题、关卡与提示、工程币/商城规则、教师流程、职业回顾。
- 每关必有：学生动作、界面反馈、提交产物、通过条件、失败提示、求助和教师介入。
- NPC 只给可追溯建议；客观测试由程序判定，安全与实物由教师签核。
- 交付：第一单完整脚本、任务/测试数据、NPC 输入输出与评审样例、手册节号、试教观察表。

### E. 总控与集成：接口、后端、验证和版本

- 负责项目骨架、分支/worktree 协作、公共接口与数据版本、个人作品权限、NPC 服务端接入、教师服务、集成和端到端验收。
- 单一公共依赖/锁文件维护者；专项不得同时修改公共入口和配置。先拆组件和接口，再并行。
- 后端工作量变大时另设独立后端专项，由总控协调，不隐形塞给“UI 支持”。
- 收可运行演示、测试证据和限制，不只收“已完成”报告。统一审核跨专项更改与发布准备。

## 6. 开发顺序与阶段门槛

### P0：校准原型与验证关键选择

- 保留当前原型，建立独立版本基线；冻结一单、一种板卡、有限元件与第一版语法。
- A/B 完成模板到受限程序结构的方案及小样；D 定义独立客户测试；E 定义版本和权限。
- C 并行做风格小样，不批量制作全部商城/办公室资产。
- 退出证据：语言和硬件的关键风险有实际实验结果，仍未确认项被明确隔离。

### P1：真正的一单闭环

入职 → NPC 需求评审 → 手册 → 虚拟接线 → 自己搭积木 → 客户需求测试 → 轻代码变更 → 复测 → 编译导出同版源码 → 教师安全检查 → 真机测试和验收。

- A/B 先贯通输入输出；D 提供任务数据；C 在已冻结布局上接入视觉；E 集成后台、NPC、教师队列与版本。
- 如硬件尚不可用，可交付软件演示，但不得将 P1 标为实物闭环完成。
- 退出证据：一名学生在不让开发者手改状态的情况下完成；更改代码或接线后旧证据失效；AI 故障可救援。

### P2：课堂可用

- 跨设备恢复、个人作品隔离、教师走访看板、求助/验收排队、弱网与重试、本人多端编辑冲突处理、纸电手册一致。
- 用零基础内部试玩校准语法、提示和时长；真实未成年人参与前完成相关数据授权与运营准备。
- 退出证据：个人流程及多用户隔离可验证，安全请求与验收不会丢失、重复或越权。班额、师资及具体容量目标暂缓，不作为当前开发的前置问题。

### P3：游戏拓展

- 工程币、有限商城、实物领料、升级订单、成果榜和职业回顾。
- 元件必须先有模型、资料、语法/库支持和实物验证，再上架。
- 退出证据：重复请求不重复扣发，缺货有替代，选修未完成不影响基础结业。

### P4：试教与发布准备

- 真实设备矩阵、零基础试课、AI 成本/延迟、权限/隐私、资产许可、恢复方案。
- 修正教学时长与难度，关闭阻碍主线和安全的缺陷；正式部署另按目标和权限执行。
- 不先给未经验证的固定工期承诺；每阶段用演示和证据验收，再估下一段。

### 8.1 冲突处理和数据模型调整

- 旧 PRD/V1.1 开发文档中的小组共享作品、成员角色轮换、小组编辑租约、小组提交/验收及小组榜，均由最新“个人参与、不设小队、按收入排名”取代。原文保留作历史资料，后续实现和验收按本计划最新决定执行。
- 员工、工位、需求卡、接线、程序、测试、验收、收入、商城购买及领料归属学生个人；教师可查看授权课程范围，其他学生不能访问或修改他人作品。班级/场次可作为未来组织范围，但不是团队协作单元。
- 收入账本与可消费余额分开；候选规则为完成订单得到收入，购买模块扣余额但不减少累计收入。该会计口径、同分顺序和撤销规则仍为设计建议，不假装用户已确认细则。发放依据真实验收且幂等，不能靠前端改数或模型直接发钱。
- 旧文档中的 UNO R3、固定 A0/D9/450 阈值是原型假设。用户确认的是 Arduino Uno 家族；明确代际与实物后更新编译目标和元件资料。
- 《深圳 I/O》继续作为公司世界观、手册与任务体验参考，不采用其专用编程语言。简写 C++ 的函数封装、允许语法及展开方式由 A 线验证后形成规格。

### 8.2 Agent 烧录两条候选路径

两条路径均处于方案阶段。Agent 负责调用经过限制的编译/上传工具，不根据描述重新生成一份“差不多”的学生程序，也不因对话说成功就写入实物完成。

**路径 A：学生电脑本地烧录**

1. 学生在自己的电脑安装选定的 Trae 类 agent 和受支持 Arduino 命令行工具/驱动；具体产品、系统支持、账号/费用和安装权限待验证，不能假定已安装。
2. 网站导出或经授权下载学生本次提交的源码与清单，包含个人提交 ID、程序/接线版本、板卡目标、依赖版本及源码摘要。板卡用 USB 接在该学生电脑。
3. Agent 在限定项目目录调用固定编译命令，明确选择目标板卡与串口；教师完成接线安全检查后执行上传。命令失败给出真实日志，不自动扩大权限、改安全设置或选择其他串口。
4. 验证学生机操作系统/驱动/USB、设备重连、多个串口辨认、编译与上传失败恢复，以及是否把代码或聊天发送至该 agent 的服务商；实际数据传输须符合已获授权范围。

**路径 B：我方电脑集中烧录**

1. 学生将自己的实际提交代码上传到项目服务；服务鉴权并生成不可变提交，脚本只下载指定学生、指定版本的原文件与清单，校验摘要，不能下载“最新文件”后混用版本。
2. 对应 Uno 必须实际连接到我方电脑，或另有经验证的受控设备接入。单纯下载代码不等于能够烧录学生远处的板卡；当前不假定已有远程串口能力。
3. 每个烧录任务绑定学生、源码摘要、接线版本、板卡/串口及操作人。采用单设备占用和明确队列，防止把甲的代码烧到乙的板；重试不得悄悄改代码或重复结算。
4. 学生上传内容视为不可信输入。限制文件类型/大小、目录路径、依赖白名单和命令参数；编译用隔离工作区和资源限制，不执行上传的脚本或拼接任意 shell 命令。Agent 仅能操作所需目录与设备，不读取无关文件。
5. 验证上传鉴权、过期链接、错误用户/摘要、断网、重复请求、队列取消、板卡拔插和任务日志；保留可追溯结果，不把下载成功或编译成功标为上传成功。

**两条路径共同验收与选型依据**

- 用同一份已通过软件检查的源码，记录工具链/FQBN/依赖、源码摘要、编译产物、目标串口、真实上传日志和教师现场功能确认。
- 无可靠硬件读回时，如实写“上传工具报告成功，功能由教师现场验证”，不宣称自动证明设备当前一定运行该版本。
- 代码/接线变化后重新验证，旧安全签核不能覆盖新的危险接线；模型不能代替现场安全批准。
- 对比安装成本、学生操作复杂度、队列等待、设备错配风险、成本和代码隐私后选择主路线与备用路线。当前不替用户安装软件、不调用第三方 agent、不上传学生代码、不烧录板卡。
